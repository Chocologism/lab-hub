# 给执行 agent 的任务

请执行本目录 README.md 中的 LabHub 独立上云迁移流程。先通读 README.md、项目 AGENTS.md 和所需技能，再根据当前授权推进。

目标：LabHub 部署于云端服务器，组员通过固定 HTTPS 域名使用；保留现有功能和获准迁移的数据。主方案为云服务器，Linux、2 核 4 GB、至少 60 GB SSD，Docker Compose + Caddy + FastAPI + 单机 SQLite，独立对象存储保存加密备份。

这是一份交接任务，不代表已购买资源或已获准立即停止旧服务。先完成本地代码修补、备份工具验证、容器构建、独立测试库验收和可审阅部署配置；缺少域名、云端访问、备案主体或具体切换窗口时，集中列出缺失项。读取当前会话已有授权，不重复索要已给出的许可。购买、实际数据导出、停服、DNS 和公网发布遵循届时用户明确的执行范围。

必须保持：

- 旧服务器不再承担正式网站、隧道入口、定时任务、备份目标或故障回退。只做获准的一次性导出和旧服务退役；不得为了测试或回退重新启动它。
- 代码仓库为 https://github.com/<your-username>/lab-hub.git。
- 本地数据库不是生产数据源。源为生产服务器：/srv/lab-hub/backend/labhub.db；执行前以进程打开文件和配置重新确认。
- 修改前先 git pull；Codex 不执行任何 git push。二进制数据库冲突不可按文本自动合并，不覆盖已积累的数据。
- 不修改 UI 样式；若确需修改，先读 design.md。可独立新增部署和迁移文件。
- templates 是待落地的配置，不是已经可投产的实现。LABHUB_ENV、REQUIRE_EXISTING_DATABASE、LABHUB_MAIL_ENCRYPTION_KEY、LABHUB_ALLOWED_ORIGINS 和 /api/ready 必须先按 README 的接口约定实现；不能只设置变量就宣称生效。
- 不输出数据库内容、成员个人信息、邮箱密码、JWT、邀请码或云凭据。数据库、备份、真实 .env、镜像导出包不得提交 Git。
- 源库开启 WAL，使用 scripts/sqlite_bundle.py 的一致备份接口；不直接复制运行中的主 .db。所有写入、重加密和演练只针对副本。
- 公网前处理默认密钥、固定邀请码、邮箱密钥耦合、SSE 鉴权、上传与隐私权限、登录/邮箱同步限流。迁移用户与权限时不得重建演示账号。
- 回退在独立云环境完成；有新业务写入后不能直接恢复上线前旧库。

请维护一份不含秘密的执行记录，列出阶段状态、代码 SHA、镜像 ID/摘要、备份 SHA-256、验收结果、当前阻塞项和下一步。最后交付可复现的部署配置、测试结果、备份恢复演练和明确的退役状态。尚未实测的项目必须标为未验证。

建议交付顺序：确认输入 → 保护数据和核对代码 → 公网准备补丁与测试 → 独立云环境准备 → 一次性数据导出与 stb 退役 → 副本演练 → 备案/DNS/HTTPS → 正式切换 → 备份恢复验收。
